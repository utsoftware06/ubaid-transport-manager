# Manual Voucher Adjustment Runtime Test Plan

Run the preflight, migration, post-verifier, and summary verifier in that order. The SQL files are read-only except for the forward-only migration; do not run them against production until the deployment window is approved.

1. In a tenant with a finalized Manual Voucher, note the real `expenses.id`, the immutable Manual settlement values, and the current Owner/Gari balance. Confirm the same Voucher has no Movement Group requirement.
2. Open **Adjustment** on the finalized Manual Voucher. Enter freight adjustment `20000`, expense adjustment `0`, and a reason. Save and finalize. Verify one `manual_voucher_adjustments` row is finalized, the original settlement row is unchanged, exactly one `manual_chakkar_adjustment` Owner/Gari transaction is linked by `source_manual_adjustment_id`, and Owner/Gari balance increases by `20000`.
3. Create a separate adjustment with freight `0` and expense `10000`. Verify net adjustment `-10000` and Owner/Gari decreases by `10000`. Create another with expense `-5000`; verify net adjustment `+5000` and Owner/Gari increases by `5000`.
4. Confirm the Manual Voucher Adjustment flow creates no Cashbook rows and no Diesel payment/allocation rows. Confirm finalized adjustments cannot be edited or deleted through the RPCs. Reverse one finalized adjustment; verify the inverse is a separate finalized record and one opposite Owner/Gari transaction, while the original adjustment and settlement remain unchanged.
5. In Monthly Hisab v3 for the corresponding settlement period, verify each Manual row displays original Chakkar Net, adjustment total, and adjusted net (`original + adjustments`); summary freight, expenses, and profit reconcile to the adjustments. Verify existing Bilty adjustment rows and Monthly Hisab Bilty values remain unchanged.
6. Open Monthly Hisab **View Voucher** on two rows that share the same displayed Voucher number. Confirm each opens the details modal for the exact `row.voucher_id` / `expenses.id`; verify no lookup uses `expense_no`.
7. In the Manual Voucher view, verify date, vehicle, optional driver, Chakkar Days, remarks, freight rows, expense snapshot, Diesel pump/litres/rate/total/paid/remaining/status/slip, original settlement, adjustment history, and adjusted Chakkar Net. Confirm finalized view is read-only.
8. Attempt to read or write an adjustment for a different Adda as an Adda Admin/Operator; server-side RPC must reject cross-tenant access. Confirm Super Admin still supplies an explicitly selected authorized Adda through the existing application context.
