# Print system coverage

This inventory reflects the current repository print entry points and integrations. The new layouts use the shared print preview/settings foundation, document-owner branding, English/Urdu labels, and browser Print / Save as PDF. Legacy print actions are retained where a legacy implementation existed. Availability can be blocked for mixed or unresolved Adda ownership; the UI must not substitute another Adda's branding.

The four stable layout IDs are `traditional_pad`, `modern_professional`, `compact_pad`, and `detailed_a4`. Shared presentation rendering is presentation-only: module adapters pass existing rows, totals, balances, and references without recalculating accounting.

## Not applicable / limitations

- A separate Oil master-list, Tyre entry slip, or expense-only report Print action does not exist in the current UI; no new business document type was invented.
- The older Vehicle Document row action remains a browser/page-print fallback; the separate Print Selected and Print All controls open the shared four-layout preview.
- The Parchi event fallback is the complete existing Parchi history; there is no separately persisted settlement-receipt object.
- A shared print preview is withheld when document owner Adda is missing, mixed, or not authorized. Existing authorized page data is not broadened by print presentation code.
- Print and PDF layout still depend on the user's browser/printer settings. Browser/PDF visual QA should be repeated manually for representative A4/A5 Urdu and long-table output; this change did not claim physical-printer verification.
